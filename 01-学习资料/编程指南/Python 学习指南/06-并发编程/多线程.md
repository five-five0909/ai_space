# Python 多线程

> Python 多线程：threading 模块，以及 GIL（全局解释器锁）的影响

## 一、核心组件速查

| 组件 | Python 实现 | 说明 |
|------|-------------|------|
| 创建线程 | `threading.Thread` | 创建新线程 |
| 线程任务 | 函数/可调用对象 | 传递给 `target` 参数 |
| 互斥锁 | `threading.Lock` | 基本锁，不可重入 |
| 可重入锁 | `threading.RLock` | 同一线程可多次获取 |
| 屏障 | `threading.Barrier` | 等待多个线程到达 |
| 信号量 | `threading.Semaphore` | 控制并发访问数量 |
| 线程安全队列 | `queue.Queue` | FIFO 队列，线程安全 |
| 线程池 | `concurrent.futures.ThreadPoolExecutor` | 管理线程生命周期 |

## 二、GIL 对科研计算的影响

### GIL 是什么？

全局解释器锁（GIL）确保同一时刻只有一个线程执行 Python 字节码。

### GIL 的影响场景

| 场景 | GIL 影响 | 推荐方案 |
|------|----------|----------|
| **CPU 密集计算**（矩阵运算、数值积分） | 严重 | 多进程（`multiprocessing`） |
| **I/O 密集任务**（文件读写、网络请求） | 较小 | 多线程 |
| **混合任务**（数据加载+预处理） | 中等 | 多进程 + 多线程组合 |
| **C 扩展计算**（NumPy、PyTorch 运算） | 无影响 | 任意方案 |

### 典型问题示例

```python
# ❌ 错误：多线程加速 CPU 密集任务
import threading

def heavy_compute(n):
    return sum(i * i for i in range(n))

threads = [threading.Thread(target=heavy_compute, args=(10**6,)) for _ in range(4)]
# 结果：比单线程更慢（线程切换开销 + GIL）

# ✅ 正确：使用多进程
from multiprocessing import Pool

with Pool(4) as p:
    results = p.map(heavy_compute, [10**6] * 4)
```

## 三、科研实战：DataLoader 的 num_workers 原理

### DataLoader 工作机制

PyTorch 的 `DataLoader` 使用多进程加载数据：

```python
from torch.utils.data import DataLoader

loader = DataLoader(
    dataset,
    batch_size=32,
    num_workers=4,  # 使用 4 个子进程加载数据
    pin_memory=True  # 锁页内存，加速 GPU 传输
)
```

### num_workers 选择指南

| 数据规模 | 推荐值 | 原因 |
|----------|--------|------|
| 小数据集（<1GB） | 0 或 2 | 避免进程创建开销 |
| 中等数据集（1-10GB） | 4-8 | 平衡加载速度与内存 |
| 大数据集（>10GB） | 8-16 | 最大化 I/O 并行 |
| SSD 存储 | 可适当增加 | I/O 不是瓶颈 |
| HDD 存储 | 保守设置 | 避免磁盘争用 |

### 常见问题

```python
# 问题1：内存不足
# 解决：减少 num_workers 或使用 pin_memory=False
loader = DataLoader(dataset, num_workers=2, pin_memory=False)

# 问题2：Windows 多进程错误
# 原因：Windows 使用 spawn，需保护主模块
if __name__ == '__main__':
    loader = DataLoader(dataset, num_workers=4)
    for batch in loader:
        pass

# 问题3：数据加载慢于训练
# 解决：增加 num_workers 或优化数据预处理
loader = DataLoader(dataset, num_workers=8, prefetch_factor=2)
```

## 四、多线程 vs 多进程选择

### 决策流程图

```
任务是否涉及大量 I/O（文件/网络）？
├── 是 → 使用多线程（threading）
└── 否 → 任务是否涉及大量 CPU 计算？
    ├── 是 → 使用多进程（multiprocessing）
    └── 否 → 使用多线程即可
```

### 详细对比

| 维度 | 多线程 | 多进程 |
|------|--------|--------|
| **内存开销** | 低（共享内存） | 高（独立内存） |
| **启动速度** | 快 | 慢（需复制进程） |
| **通信成本** | 低（共享变量） | 高（需序列化） |
| **GIL 影响** | 受限 | 不受限制 |
| **适用场景** | I/O 密集 | CPU 密集 |
| **数据隔离** | 差 | 好 |
| **调试难度** | 较高（竞态条件） | 较低 |

### 科研场景对照表

| 科研任务 | 推荐方案 | 理由 |
|----------|----------|------|
| 批量下载论文/数据集 | 多线程 | 网络 I/O 等待时间长 |
| 数据增强（图像翻转、裁剪） | 多进程 | CPU 密集计算 |
| 训练模型（GPU 计算） | 单进程 | CUDA 已并行 |
| 超参数搜索（多组实验） | 多进程 | 独立实验，避免干扰 |
| 实时日志监控 | 多线程 | 文件 I/O |
| 特征工程（pandas 处理） | 多进程 | 数据处理 CPU 密集 |
| Web 爬虫采集数据 | 多线程 | 网络 I/O 瓶颈 |

## 五、实战代码模式

### 模式1：线程池处理 I/O 任务

```python
from concurrent.futures import ThreadPoolExecutor
import requests

urls = ['https://api.example.com/data/{}'.format(i) for i in range(100)]

def fetch(url):
    response = requests.get(url)
    return response.json()

with ThreadPoolExecutor(max_workers=10) as executor:
    results = list(executor.map(fetch, urls))
```

### 模式2：多进程并行计算

```python
from multiprocessing import Pool
import numpy as np

def process_chunk(data):
    return np.fft.fft(data)

data_chunks = [np.random.rand(10000) for _ in range(8)]

with Pool(processes=4) as pool:
    results = pool.map(process_chunk, data_chunks)
```

### 模式3：生产者-消费者模式

```python
import threading
import queue

data_queue = queue.Queue(maxsize=100)

def producer():
    for i in range(1000):
        data_queue.put(i)

def consumer():
    while True:
        item = data_queue.get()
        if item is None:  # 哨兵值
            break
        # 处理数据
        data_queue.task_done()

# 启动线程
threading.Thread(target=producer).start()
for _ in range(4):
    threading.Thread(target=consumer).start()
```

## 六、最佳实践

### 线程安全检查清单

- [ ] 共享资源是否加锁？
- [ ] 是否避免死锁（按固定顺序获取锁）？
- [ ] 是否使用线程安全的数据结构（`queue.Queue`）？
- [ ] 是否正确处理异常（避免线程静默失败）？
- [ ] 是否设置超时（避免无限等待）？

### 性能优化建议

1. **减少锁粒度**：锁住最小必要代码块
2. **使用局部变量**：避免不必要的共享
3. **批量处理**：减少线程切换频率
4. **监控资源**：使用 `psutil` 监控 CPU/内存

```python
import psutil
import threading

def monitor_resources():
    print(f"CPU: {psutil.cpu_percent()}%, Memory: {psutil.virtual_memory().percent}%")

# 每 5 秒监控一次
timer = threading.Timer(5.0, monitor_resources)
timer.start()
```

## 七、常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| `RuntimeError: can't start new thread` | 线程数过多 | 使用线程池 |
| 程序卡死不响应 | 死锁 | 检查锁获取顺序 |
| 数据竞争 | 未加锁访问共享变量 | 使用 `Lock` 或 `Queue` |
| 内存泄漏 | 线程未正常退出 | 使用 `with` 或设置 `daemon=True` |
