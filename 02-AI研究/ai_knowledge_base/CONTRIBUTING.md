## 文档规范

### 文档结构模板

每篇文档应包含以下部分：

```markdown
# [主题名称]

## 大白话解释

这玩意儿到底是啥？用最通俗的语言解释...

## 核心概念

- 概念1：...
- 概念2：...

## 数学原理

### 核心公式

$$
\text{公式}
$$

### 推导过程

1. 步骤1
2. 步骤2

## 代码实现

```python
import torch
# PyTorch 代码示例
```

## 实际应用

- 应用场景1：...
- 应用场景2：...

## 推荐论文

1. **论文标题** - 核心贡献：...
2. **论文标题** - 核心贡献：...
3. **论文标题** - 核心贡献：...

## 扩展阅读

- [相关主题1](链接)
- [相关主题2](链接)
```

### 文件命名规范

- 目录名：`数字前缀-英文主题名`（如 `01-mamba`）
- 文档名：统一使用 `README.md`

### Markdown 格式要求

- 使用 ATX 风格标题（`#` 而非下划线）
- 代码块必须指定语言类型
- 数学公式使用 `$...$`（行内）或 `$$...$$`（块级）
- 链接使用相对路径

## 提交流程

1. **Fork 仓库**
2. **创建分支**：`git checkout -b feature/your-topic`
3. **编写/修改文档**
4. **本地预览**：确保 Markdown 渲染正确
5. **提交更改**：
   ```bash
   git add .
   git commit -m "docs: 添加/更新 [主题名称]"
   ```
6. **推送分支**：`git push origin feature/your-topic`
7. **创建 Pull Request**

### 提交信息规范

使用 Conventional Commits 格式：

- `docs: 添加新文档` - 新增文档
- `docs: 更新XX文档` - 更新现有文档
- `fix: 修正XX文档中的错误` - 修正错误
- `style: 格式化XX文档` - 格式调整

## 内容要求

- [ ] 大白话解释通俗易懂，避免术语堆砌

- 使用简体中文
